## 三、实验整体逻辑分析

### 2.1 本章节的逻辑主线

本实验围绕内核线程的建立和运行展开。内核先准备物理页及虚拟内存映射，再建立线程控制块、内核栈和初始上下文，最后由调度器选择可运行线程并完成上下文切换。成员 A 负责其中的内存管理部分，为页表和后续内核资源分配提供基础。

### 2.2 功能的逐步实现

1. **迁移物理内存管理并补齐页表操作。** `page_init()` 建立物理页描述信息并把空闲页交给 Best Fit。具备物理页分配能力后，`get_pte()` 才能在需要时申请中间页表页，映射接口才能更新具体页表项。
2. **建立并初始化内核线程。** 内核需要先准备可供调度的线程对象，包括控制块、内核栈和初始执行状态。
3. **调度和切换内核线程。** 待线程进入可运行状态后，再由调度器选择目标线程，保存原线程现场，恢复目标线程现场。

## 四、实验内容与实现

### 功能模块：虚拟内存页操作

**负责人：** 2413195-钟沁涵

#### 模块功能描述

**需要实现/修改的函数：**

```c
// code/kern/mm/default_pmm.c
static void best_fit_init(void);
static void best_fit_init_memmap(struct Page *base, size_t n);
static struct Page *best_fit_alloc_pages(size_t n);
static void best_fit_free_pages(struct Page *base, size_t n);
static size_t best_fit_nr_free_pages(void);
static void best_fit_insert_block(struct Page *base);

// code/kern/mm/pmm.c
static void page_init(void);
int page_insert(pde_t *pgdir, struct Page *page, uintptr_t la, uint32_t perm);
void page_remove(pde_t *pgdir, uintptr_t la);
static void page_remove_pte(pde_t *pgdir, uintptr_t la, pte_t *ptep);
void tlb_invalidate(pde_t *pgdir, uintptr_t la);
```

**功能说明：**

本模块在 `default_pmm.c` 中通过 `default_pmm_manager` 接入迁移后的 Best Fit 分配器。Best Fit 从能满足申请的空闲块里选择最小的一块，必要时拆分空闲块，释放后尝试与相邻空闲块合并。`page_init()` 根据设备树返回的物理内存范围，设置物理页描述符数组，并将可用页交给分配器。

`page_insert()` 借助骨架已有的 `get_pte()` 定位页表项。首次映射时增加目标页引用。重复映射到同一个物理页时更新权限，引用计数保持原值。改映射到另一物理页时，先撤销旧映射，再增加新页引用并安装新表项。`page_remove()` 查找已有映射，调用 `page_remove_pte()` 清除有效表项、使旧的 TLB 翻译失效并减少原物理页引用。计数降为零时回收物理页。删除不存在的映射时直接返回。

##### 第一次迭代

**遇到的问题：**

- 导入 Lab4 骨架后，对照压缩包发现 `default_pmm.c` 含有对 `best_fit_pmm.h` 的引用，但骨架内没有该头文件。旧实验的分配器实现通过 `best_fit_pmm_manager` 导出，Lab4 的初始化代码通过 `default_pmm_manager` 接入。
- Lab4 的 `pmm_init()` 已经包含页表检查和内核动态分配器的初始化流程。迁移时需要落实 `page_init()` 及其依赖常量，同时保留这些 Lab4 调用。

**问题解决策略：**

- 在分析迁移位置时明确保留骨架的分配器入口及检查函数。将旧版 Best Fit 逻辑接到 `default_pmm_manager`，使用骨架已有的 `default_pmm.h`。
- 按两个 `lab2` 标记插入对应代码，物理内存初始化只迁移 `page_init()` 及其相关常量。

**最终结果：**

`default_pmm.c` 和 `pmm.c` 均通过 RISC-V 目标文件编译。

##### 第二次迭代（如有）

**遇到的问题：**

- 同一个虚拟地址更新到原来的物理页时，如果先撤销旧映射，物理页只有一次引用的情况下可能被提前释放。
- 测试使用 `perm = 0` 和仅带 `PTE_W` 的参数。按 Sv39 的页表项编码，这两种情况需要补齐读位才能形成合法的目标页映射。

**问题解决策略：**

- 在设计中明确分开同页更新和换页两种路径。同页更新保持引用计数，换页时复用 `page_remove_pte()` 处理旧页。删除时先清空页表项、刷新旧翻译，再减少旧页引用计数。给 `sfence.vma` 的内联汇编加上 `"memory"` 约束，使编译器保留内存更新与刷新的顺序。
- 对上述两个测试权限组合补上 `PTE_R`，显式只执行权限仍按原值写入。

**最终结果：**

`git diff --check` 无错误输出，补齐页表函数后 `pmm.c` 重新编译成功。代码已推送到 `lab4`，提交为 [`10de740`](https://github.com/CheriaAshley/OS48Team/commit/10de7401f49797a2c043b52aa9f2a1f4b2fc3c23)。

**关键改进点总结（如有）：**

明确同页更新、换页及重复删除分别如何处理。用现有框架接口统一维护页表项、物理页引用和 TLB，按实际命令记录编译结果。

### Challenge：不同分页模式与 `get_pte()`

**负责人：** 2413195-钟沁涵

| 分页模式 | 普通 4 KiB 页的页表级数 | 每级索引位数 |
|---|---:|---:|
| Sv32 | 2 | 10 |
| Sv39 | 3 | 9 |
| Sv48 | 4 | 9 |

Sv39 从根页表到最底层需要向下走两次。`get_pte()` 的两段代码分别检查 `PDX1(la)`、`PDX0(la)` 对应的表项，必要时申请一个物理页存放下一级页表，清零后填写指向它的表项。两处承担相同的遍历操作，只是索引和层级不同。最后使用 `PTX(la)` 返回叶级表项的位置。

查找与分配可以共用遍历过程，`create` 参数决定是否允许创建中间页表。`page_remove()` 传入 `0`，`page_insert()` 传入 `1`。若需要进一步区分接口语义，可以对外提供只查找和允许创建的两个入口，内部仍复用同一份遍历逻辑。

## 六、实验总结与收获

### 对操作系统的理解

1. **已对应的操作系统原理。** Best Fit 解决连续物理页的选取和回收。多级页表记录虚拟页到物理页的映射及权限。TLB 缓存硬件翻译结果，因此修改表项后还需要处理旧翻译。引用计数则记录物理页的使用情况，用来判断撤销一条映射后物理页是否可以被回收。
2. **后续实验涉及的知识点。** 本模块采用预映射方式。按需分页、页面换入换出以及页面置换还需要结合缺页异常和后备存储实现。
