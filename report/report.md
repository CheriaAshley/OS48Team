## 三、实验整体逻辑分析

### 2.1 本章节的逻辑主线

本实验围绕内核线程的建立和运行展开。内核先准备物理页及虚拟内存映射，再建立线程控制块、内核栈和初始上下文，最后由调度器选择可运行线程并完成上下文切换。成员 A 负责其中的内存管理部分，为页表和后续内核资源分配提供基础。

### 2.2 功能的逐步实现

1. **迁移物理内存管理并补齐页表操作。** `page_init()` 建立物理页描述信息并把空闲页交给 Best Fit。具备物理页分配能力后，`get_pte()` 才能在需要时申请中间页表页，映射接口才能更新具体页表项。
2. **建立并初始化内核线程。** 内核需要先准备可供调度的线程对象，包括控制块、内核栈和初始执行状态。
3. **调度和切换内核线程。** 待线程进入可运行状态后，再由调度器选择目标线程，保存原线程现场，恢复目标线程现场。

### 功能模块：虚拟内存页操作

**负责人：** 2413195-钟沁涵

#### 模块功能描述

**需要实现/修改的函数：**

```c
// code/kern/mm/default_pmm.c
static void best_fit_init(void);
static void best_fit_init_memmap(struct Page *base, size_t n);
static struct Page *best_fit_alloc_pages(size_t n);
static void best_fit_free_pages(struct Page *base, size_t n);
static size_t best_fit_nr_free_pages(void);
static void best_fit_insert_block(struct Page *base);

// code/kern/mm/pmm.c
static void page_init(void);
int page_insert(pde_t *pgdir, struct Page *page, uintptr_t la, uint32_t perm);
void page_remove(pde_t *pgdir, uintptr_t la);
static void page_remove_pte(pde_t *pgdir, uintptr_t la, pte_t *ptep);
void tlb_invalidate(pde_t *pgdir, uintptr_t la);
```

**功能说明：**

本模块在 `default_pmm.c` 中通过 `default_pmm_manager` 接入迁移后的 Best Fit 分配器。Best Fit 从能满足申请的空闲块里选择最小的一块，必要时拆分空闲块，释放后尝试与相邻空闲块合并。`page_init()` 根据设备树返回的物理内存范围，设置物理页描述符数组，并将可用页交给分配器。

`page_insert()` 借助骨架已有的 `get_pte()` 定位页表项。首次映射时增加目标页引用。重复映射到同一个物理页时更新权限，引用计数保持原值。改映射到另一物理页时，先撤销旧映射，再增加新页引用并安装新表项。`page_remove()` 查找已有映射，调用 `page_remove_pte()` 清除有效表项、使旧的 TLB 翻译失效并减少原物理页引用。计数降为零时回收物理页。删除不存在的映射时直接返回。

### 功能模块：进程创建与初始化

**负责人：** 2413467-徐熙凯（成员 B）

#### 模块功能描述

本模块在 `kern/process/proc.c` 完成六个函数。`alloc_proc()` 分配并清零 PCB，设置初始状态 `PROC_UNINIT`、未分配 PID `-1`、内核页表物理地址及链表节点。`proc_init()` 初始化进程链表和 PID 哈希表，把当前启动现场包装为 PID 0 的 `idleproc`，复用 `bootstack`，设置 `current` 和重调度标记，再创建 PID 1、名为 `init` 的线程。

`kernel_thread()` 构造临时 trapframe：`s0` 保存目标函数，`s1` 保存参数，`epc` 指向 `kernel_thread_entry`，设置 `SPP`、`SPIE` 并清除 `SIE`。它调用 `do_fork()`，由后者依次分配 PCB、内核栈、处理地址空间接口、构造首次执行现场，然后在保存并关闭本地中断的临界区内分配 PID、登记链表与哈希表、增加进程数并唤醒线程。返回值是新线程 PID；资源不足时返回负错误码。

`copy_mm()` 依据当前实验只创建内核线程的前提，断言 `current->mm == NULL`，保持新线程 `mm == NULL`，不实现用户地址空间复制。`copy_thread()` 把 trapframe 复制到新线程内核栈高端，设置子线程 `a0 = 0`，设置初始 `sp`，并令 `context.ra = forkret`、`context.sp = proc->tf`。非零传入栈地址保存在 `tf->gpr.sp`；内核线程传入零时使用 trapframe 地址。

首次执行的设计链路为 `switch_to -> forkret -> forkrets -> __trapret -> sret -> kernel_thread_entry -> init_main`。`context` 是供 `switch_to` 使用的精简调用现场，trapframe 则是供 `sret` 恢复的完整现场。骨架 `kernel_thread_entry` 用 `move a0, s1` 传参数，再用 `jalr s0` 调用线程函数，返回后调用 `do_exit()`。当前 `do_exit()` 的 panic 是实验骨架占位行为，不属于 B 的退出回收实现。

### 功能模块：进程调度与上下文切换

**负责人：** 2413533-蔡芷涵

#### 模块功能描述

**需要实现/修改的函数：**

```c
// code/kern/process/proc.c
void cpu_idle(void);
void proc_run(struct proc_struct *proc);

// code/kern/schedule/sched.c
void schedule(void);

// code/kern/process/switch.S
void switch_to(struct context *from, struct context *to);
```

**功能说明：**

本模块负责实现内核线程的基本调度与上下文切换，使系统能够从仅完成线程创建的状态，进一步具备实际执行内核线程的能力。模块以 `idleproc` 和 `initproc` 为主要运行场景，通过调度器选择可运行线程，并完成 CPU 执行现场的保存与恢复。
`cpu_idle()` 是空闲线程的执行入口，通过循环检查当前线程的 `need_resched` 标志，在需要重新调度时调用 `schedule()`。`schedule()` 负责清除调度标志、遍历进程链表，并根据进程状态选择下一个处于 `PROC_RUNNABLE` 状态的线程。如果没有找到其他适合运行的线程，则使用空闲线程作为保底选择。
`proc_run()` 负责执行具体的线程切换操作。在切换过程中，先保护中断状态，再更新 `current` 指针，设置目标线程对应的页表基址并刷新 TLB，最后调用 `switch_to()` 完成上下文切换。`switch_to()` 使用 RISC-V 汇编保存原线程的 `ra`、`sp` 和 `s0`～`s11` 寄存器，并恢复目标线程的对应寄存器，使 CPU 能够继续执行目标线程。
在 Lab4 的实际运行过程中，`proc_init()` 完成 `idleproc` 和 `initproc` 的初始化后，内核进入 `cpu_idle()`。调度器选中 `initproc`，通过 `proc_run()` 和 `switch_to()` 切换到新线程。由于新线程的初始上下文已设置好 `forkret` 入口，因此能够继续经过 `forkrets` 和 `__trapret` 恢复执行现场，最终进入 `init_main()`，完成内核线程的首次运行。

**[SPECIFICATION]**

### Challenge：中断状态的保存与恢复

**负责人：** 2413533-蔡芷涵

本题要求分析 `local_intr_save(intr_flag); ... local_intr_restore(intr_flag);` 如何实现中断状态的保存与恢复，以及这种机制为什么能够保护内核中的关键操作。

**1. 中断开关的基本原理**

在 RISC-V 架构中，`sstatus` 寄存器的 `SIE` 位用于控制 S 模式下的全局中断使能状态。当 `SIE=1` 时，处理器允许响应已使能的相应中断；当 `SIE=0` 时，这些中断暂时不能打断当前 S 模式执行流程。

`intr_enable()` 和 `intr_disable()` 分别用于开启和关闭相应的中断使能状态。进程调度过程中需要修改 `current`、切换页表以及保存和恢复寄存器现场，这些操作应避免在状态尚未一致时被中断打断。

**2. `local_intr_save()` 的作用**

执行 `local_intr_save(intr_flag)` 时，首先保存当前中断是否开启的状态，然后关闭当前处理器的相关中断，使后续代码能够在受保护的临界区中执行。

其中，`intr_flag` 用于记录进入临界区之前的中断状态，而不是简单地固定为某个值。如果进入临界区之前中断已经关闭，就应记录这一状态，避免后续错误地重新开启中断。

**3. `local_intr_restore()` 的作用**

执行 `local_intr_restore(intr_flag)` 时，根据之前保存的 `intr_flag` 恢复中断状态。如果进入临界区前中断处于开启状态，则重新开启中断；如果原本处于关闭状态，则继续保持关闭。

因此，这两个操作不是简单地“关闭中断后再无条件开启”，而是实现了中断状态的保存和恢复，能够避免破坏调用者原有的中断控制状态。

**4. 在本实验中的应用**

在 `schedule()` 和 `proc_run()` 中，使用中断状态保护机制可以防止进程选择、`current` 更新、页表切换和上下文保存恢复过程中发生不合适的中断打断。

其基本使用形式为：

```c
bool intr_flag;
local_intr_save(intr_flag);

/* 执行需要保护的操作 */

local_intr_restore(intr_flag);
```

这种方式保护的是当前处理器上的临界区，不等同于多核环境下的全局互斥。若多个 CPU 需要同时访问共享数据，还需要使用自旋锁等同步机制。

**5. 总结**

`local_intr_save()` 和 `local_intr_restore()` 通过保存原中断状态、暂时关闭中断、执行临界区操作以及恢复原状态，实现了对关键代码的保护。在本实验的进程调度过程中，这一机制有助于保持进程控制信息、页表状态和实际执行现场的一致性，是实现可靠上下文切换的重要基础。
